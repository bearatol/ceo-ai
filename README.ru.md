# CEO AI

[English](README.md) · [Русский](README.ru.md) · [简体中文](README.zh-CN.md)

**Не знаешь, как лучше сделать? Посоветуйся с ИИ CEO.**

CEO AI помогает ИИ-ассистенту разобраться в задаче, проверить предположения,
выбрать подход и организовать работу. Вы задаёте цель и ограничения. CEO должен
объяснять выводы, менять мнение при новых фактах и выбирать процесс соразмерно задаче.

В репозитории находятся инструкции и утилиты на Python. Модель, доступ к файлам
и запуск субагентов предоставляет инструмент, в котором вы работаете.

## Что умеет CEO

- Обсуждает варианты и оспаривает существенные ошибки, в том числе собственные.
- Коротко отвечает на простые вопросы и составляет план для связанных шагов.
- Проверяет скиллы и агентов. Если чего-то не хватает, предлагает установку
  или создание подходящего компонента с учётом ваших разрешений.
- Раздаёт ограниченные задачи и проверяет доказательства выполнения.
- Для кода использует TDD, для текста и обсуждений выбирает подходящую проверку.
- Перед решениями с высокой ценой ошибки привлекает независимого ментора.

## Попробовать без установки

Склонируйте репозиторий. Команды рассчитаны на macOS, Linux и WSL:

```bash
mkdir -p "$HOME/proj"
git clone https://github.com/bearatol/ceo-ai.git "$HOME/proj/ceo-ai"
cd "$HOME/proj/ceo-ai"
```

Откройте эту папку в своём ИИ-инструменте и напишите:

```text
Прочитай CONNECT.md и примени skills/ceo/SKILL.md.
Корень экосистемы находится в этой папке.
Помоги выбрать подход к задаче: ...
Ограничения и критерии успеха: ...
```

При работе в другом проекте укажите полный путь к клону `ceo-ai` и разрешите
инструменту его читать. Само открытие папки не регистрирует скиллы и субагентов.

## Установка в Codex, Claude Code и Cursor

Сохраните клон: в нём остаются каталог, промпты ролей и утилиты. Скопируйте все
семь папок из `skills/` в **одну** папку из таблицы, сохранив файлы `SKILL.md`.
Совпадающие папки сначала сравните, чтобы не затереть существующую настройку.

| Инструмент | Для всех ваших проектов | Для одного проекта | Вызов |
| --- | --- | --- | --- |
| Codex | `~/.agents/skills/` | `.agents/skills/` | `$ceo` |
| Claude Code | `~/.claude/skills/` | `.claude/skills/` | `/ceo` |
| Cursor | `~/.cursor/skills/` | `.cursor/skills/` | `/ceo` в чате Agent |

Пути и способы вызова сверены 11 октября 2026 года с документацией
[Codex](https://developers.openai.com/codex/skills/),
[Claude Code](https://code.claude.com/docs/en/skills) и
[Cursor](https://cursor.com/docs/skills). Здесь под Claude подразумевается
**Claude Code**, а не чат на claude.ai.

Для личной установки выполните только одну строку на выбор:

```bash
ceo_skill_dir="$HOME/.agents/skills"   # Codex
```

```bash
ceo_skill_dir="$HOME/.claude/skills"   # Claude Code
```

```bash
ceo_skill_dir="$HOME/.cursor/skills"   # Cursor
```

Затем в том же терминале Bash или Zsh, находясь в папке `ceo-ai`, выполните блок
ниже. Он проверяет все назначения до копирования и останавливается при совпадении имён.

```bash
(
  set -eu
  : "${ceo_skill_dir:?Choose a skill destination first}"
  test -f CONNECT.md
  test -f skills/ceo/SKILL.md
  for ceo_source in skills/*; do
    ceo_name=$(basename "$ceo_source")
    if [ -e "$ceo_skill_dir/$ceo_name" ] || [ -L "$ceo_skill_dir/$ceo_name" ]; then
      printf 'Already exists; compare manually: %s\n' "$ceo_skill_dir/$ceo_name" >&2
      exit 1
    fi
  done
  mkdir -p "$ceo_skill_dir"
  for ceo_source in skills/*; do
    cp -R "$ceo_source" "$ceo_skill_dir/"
  done
)
```

Для установки в один проект задайте в `ceo_skill_dir` полный путь к папке этого
проекта из таблицы. В Windows без WSL склонируйте репозиторий через Git и
скопируйте те же папки проводником. `~` обозначает домашнюю папку пользователя,
а относительные пути отсчитываются от целевого проекта. Не создавайте несколько
копий одного скилла в папках, которые читает ваш инструмент.

Откройте новый сеанс. В Codex вызовите `$ceo`, в Claude Code или Cursor используйте
`/ceo`. Затем отправьте запрос, заменив подсказку в скобках настоящим путём:

```text
Корень экосистемы CEO AI: <полный путь к клону ceo-ai>.
Прочитай его CONNECT.md. Работай над текущим проектом.
Цель: ...; срок: ...; критерии успеха: ...
Проверь предположения, которые могут повлиять на результат.
```

Копии скиллов не содержат каталога. После переноса клона сообщите ассистенту новый путь.

## Как пользоваться

Для совета: «Сравни два подхода. Какие мои предположения пока ничем не подтверждены?»

Для реализации: «Исправь ошибку. Сначала воспроизведи её падающим тестом,
затем внеси минимальную правку и проверь результат».

Для дорогого решения: «Проверь план миграции. До принятия решения попроси
независимого ментора оценить предположения, откат и альтернативы».

Ожидаемый ответ: рекомендация или результат, подтверждающие факты и существенные
ограничения. CEO должен уважать осознанный выбор пользователя и не возвращаться
к закрытым вопросам без новых данных. Указывайте бюджет, срок и разрешения,
если они влияют на решение.

## Субагенты и независимый ментор

После установки скиллов основной ассистент может вести работу по методике CEO.
Именованные роли нужно отдельно зарегистрировать. Четыре файла в `agents/`
содержат переносимые промпты, а не готовые конфигурации для каждого приложения.
Начните со **скилла CEO в основном чате** и подключайте специалистов по необходимости.

| Инструмент | Файл роли в проекте | Ограничение ментора на чтение |
| --- | --- | --- |
| Codex | `.codex/agents/decision-mentor.toml` | `sandbox_mode = "read-only"` |
| Claude Code | `.claude/agents/decision-mentor.md` | `tools: Read, Glob, Grep` |
| Cursor | `.cursor/agents/decision-mentor.md` | `readonly: true` |

Создайте файл в штатном формате: имя `decision-mentor`, короткое описание и текст
роли из `agents/decision-mentor.md`. Укажите разрешённый путь к клону для чтения
каталога, выбранных скиллов и протокола. В Codex текст помещается в
`developer_instructions`, в Claude Code и Cursor после YAML-заголовка.
Форматы: [Codex](https://developers.openai.com/codex/subagents/),
[Claude Code](https://code.claude.com/docs/en/sub-agents),
[Cursor](https://cursor.com/docs/subagents).

Аналогично при необходимости подключите `engineer` и `qa-reviewer`, выдав только
нужные для работы инструменты и сохранив ограничения ролей. Отдельный **агент CEO**
работает на чтение и делегирует изменения. **Скилл CEO** использует существующие
права основного ассистента. Перед делегированием проверьте, что роль доступна
и её права ограничены. Наличия файла для этого недостаточно.

Эти настройки не создают полноценную изоляцию с отключённой сетью. Проверку
безопасности должен выполнять специалист с ограничениями, которые требует
проект. Ментор и QA его не заменяют. Без субагентов CEO может давать советы и
выполнять разрешённую работу, но обязан сообщить об отсутствии независимой
проверки и отложить решение, для которого она обязательна.

## Проверка комплекта

Из папки репозитория, с Python 3.10 или новее. Сторонние пакеты не нужны.

```bash
python3 tools/team/team.py --home . list --type agent
python3 scripts/catalog.py --pack . validate
python3 -m unittest discover -s tests -p 'test_*.py'
python3 scripts/check.py
```

В Bash также доступны `bash tests/test.sh` и `bash scripts/doctor.sh`.
Они проверяют комплект, но не регистрацию ролей в приложении и не поведение модели.

Необязательная инвентаризация для POSIX:

```bash
python3 scripts/ceo_inventory.py --home .
python3 scripts/ceo_inventory.py --home . --refresh
```

Первая команда читает метаданные, вторая при наличии разрешения записывает
игнорируемый Git кэш. Утилита отклоняет симлинки и неподдерживаемые структуры.
В Windows без WSL и для других структур используйте разрешённые средства
обнаружения вашего инструмента. Обнаружение не устанавливает компоненты
и не выдаёт им права.

## Обновление, удаление и неполадки

Изучите изменения перед обновлением. В чистом клоне выполните
`git pull --ff-only`, повторите проверки, затем сравните и обновите только
установленные вами копии скиллов и конфигурации ролей. Они не обновляются
автоматически. Для удаления уберите только свои установленные копии и роли,
сохранив чужие файлы и локальные правки. Затем перезапустите инструмент.

Если `ceo` не появился, проверьте папку назначения, имя `SKILL.md`, совпадения
имён и настройки скиллов. Если не найден каталог, явно укажите путь к клону.
Если недоступна роль, проверьте её регистрацию и фактические права.

## Состав и ограничения

Семь скиллов, четыре промпта ролей, контракты заданий и результатов, утилита для
пакетов задач и необязательный индексатор. Технические детали на английском:
[руководство](docs/CEO_GUIDE.md), [подключение](CONNECT.md) и
[происхождение файлов](docs/PROVENANCE.json).

Права приложения и обязательные проверки проекта сохраняют силу. В комплекте
нет автоматической установки недостающих компонентов или изолированного
security-reviewer. Инструкции не выдают доступ. Полный сценарий подключения
пока не проверен внутри всех трёх приложений.

Часть практик планирования и ревью взята за ориентир из Superpowers. Его промпты
не включены. Преимущество в качестве и экономии пока не подтверждено сравнительными
измерениями. Исходные уведомления сохранены в [лицензии MIT](LICENSE).
