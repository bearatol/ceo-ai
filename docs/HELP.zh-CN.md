## 找不到技能

在安装 CEO AI 的同一个项目中开启新会话。Codex 使用 `$ceo-ai`，
Claude Code 和 Cursor 使用 `/ceo-ai`。如果仍找不到，请向智能体发送：

> 请按照 https://github.com/bearatol/ceo-ai 中的 INSTALL.md 检查当前项目的 CEO AI 安装。
> 确认我使用的应用、技能目录和文件，再单独确认应用是否能加载 ceo-ai。
> 保留现有文件和权限。

安装器检查的是文件，应用是否加载技能需要另行确认，不同版本的应用也可能表现不同。
如果应用不能启动其他 AI 助手，CEO 仍可以参与讨论，但必须说明哪些独立检查无法完成。

## 安装停止或请求授权

请让智能体说明具体缺少哪项权限或工具。默认安装器需要 Git 和 Python 3.10 或更新版本。
安装这些工具可能需要你的环境授权。APM 是可选的。从 0.3.0 起，默认安装器支持原生 Windows。智能体可通过 `py -3` 或 `python`
调用已有的 Python 3.10+。项目应位于本地磁盘的普通文件夹；不支持网络路径和 junction。
WSL 项目使用 WSL 内的 Linux 安装方式。

如果目录已存在，或者已安装的文件被修改过，请让智能体展示冲突并帮助保留改动。
更新和卸载时应沿用原来的安装方式，不要要求强制覆盖文件。

## 更新中断

请让智能体检查错误，并按照 [INSTALL.md 中的恢复说明（英文）](../INSTALL.md)处理。
该流程适用于本项目安装器。APM 管理自己的状态，恢复方式可能不同。
在检查完成前保留错误信息和本地改动。

## 从旧版手动安装迁移

0.1.0 的说明要求复制多个独立技能，并通过 `$ceo` 或 `/ceo` 调用。
从 0.2.0 开始，只需安装一个名为 `ceo-ai` 的完整技能。
新安装器无法确认旧版手动复制文件的归属。

请让智能体找到旧副本，与原始版本比较并识别你的改动。先确认哪些旧文件可以备份和移除，
再授权清理。随后在项目中安装 `ceo-ai` 并使用新名称。保留其他技能和现有配置。

## 获取帮助

[提交 issue](https://github.com/bearatol/ceo-ai/issues/new/choose)，说明应用及其版本、
操作系统、CEO AI 版本、安装方式和完整错误信息，并描述预期与实际结果。
请从示例中移除私有项目内容、提示词、凭据和个人路径。

发现潜在安全漏洞时，请使用[私密报告渠道（英文说明）](../SECURITY.md)。
提交修复或翻译前，请阅读[贡献指南（英文）](../CONTRIBUTING.md)。
