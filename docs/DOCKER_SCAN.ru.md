# Дополнительная проверка через Docker

[English](DOCKER_SCAN.md) · [Русский](DOCKER_SCAN.ru.md) · [简体中文](DOCKER_SCAN.zh-CN.md)

Начни со [встроенной проверки](QUICKSTART.ru.md). Этот необязательный вариант
добавляет NVIDIA SkillSpector 2.12.0 через отдельный плагин CEO AI Security.
Он использует процессор, память и диск, без платных API и вызовов LLM. Токены
чата с помощником учитываются отдельно. Облачной замены нет.

Можно отправить агенту готовый запрос. Ниже — те же шаги вручную:

```text
Помоги настроить и выполнить одну дополнительную локальную проверку CEO AI Security по этой инструкции.
Сначала проверь систему, Python, Docker и Buildx. Перед установкой инструментов,
загрузкой/сборкой образа и доступом к файлам объясни точную область действий;
используй прежние разрешения и уточни недостающие.
Используй проверенный рецепт tools/security-image, проверь неизменяемый ID образа
и версию 2.12.0, затем испытай адаптер на искусственном примере.
Проверь только разрешённый скилл, с согласованными приватными путями рабочей папки,
отчёта и Unix-сокетом. Не используй внешние API и не запускай код скилла.
Покажи пробелы проверки, доверие оставь неподтверждённым.
```

## 1. Проверь требования и установи дополнительный плагин

Нужны macOS или Linux (POSIX), Python 3.10+ на компьютере и локальный **Docker-хост
с родной архитектурой ARM64 и контейнерами Linux ARM64**. В образе используется
Python 3.12. Этот рецепт не охватывает Intel/AMD64, эмуляцию, обычную Windows и
удалённые Docker-демоны. Нужна проверенная копия репозитория CEO AI с каталогом
`tools/security-image/` и собранным дополнительным адаптером. Команды выполняй из неё.

Если Docker отсутствует, установи подходящий вариант по [официальной инструкции](https://docs.docker.com/get-started/get-docker/)
и запусти демон. Установка и изменение системных прав требуют отдельного согласия;
плагин этого не делает. Проверь:

```sh
python3 --version
docker version
docker buildx version
docker info --format '{{.OSType}}/{{.Architecture}}'
docker context inspect --format '{{.Endpoints.docker.Host}}'
```

Нужны Linux `aarch64`/`arm64` и локальный сокет `unix:///…`. Сохрани его адрес для
адаптера. BuildKit должен поддерживать `ADD --checksum` и `RUN --network=none`.
Если Buildx отсутствует, следуй [официальной инструкции установки](https://github.com/docker/buildx#installing)
только после отдельного согласия. Не переходи на старый сборщик.
Установи `ceo-ai-security` по [инструкции плагина](PLUGINS.md#опциональный-ceo-ai-security).
Сама установка не разрешает сканирование или сборку образа.

## 2. Собери образ с закреплёнными версиями

До разрешения на сборку проверь пять файлов в `tools/security-image/`. Контекст
сборки — только этот каталог, не домашняя папка и не весь проект. Загрузка базового
образа, колёс PyPI и закреплённого исходника GitHub требует сети. Затем сборка и
установка сканера идут без сети от непривилегированного пользователя. Поэтому
первоначальная сборка целиком **не является офлайн**.

```sh
DOCKER_BUILDKIT=1 docker build -t ceo-ai-skillspector:2.12.0 tools/security-image
```

Рецепт закрепляет digest базового образа, checksum исходника и хеши бинарных
зависимостей. Это проверка целостности, а не сертификат безопасности. Основа:
Docker [`ADD --checksum`](https://docs.docker.com/reference/dockerfile/#add---checksum),
[`RUN --network=none`](https://docs.docker.com/reference/dockerfile/#run---networknone)
и [проверка хешей в pip](https://pip.pypa.io/en/stable/topics/secure-installs/).
Не отключай хеши и не включай сеть этапу сборки ради обхода ошибки.

## 3. Сохрани ID образа и проверь версию

```sh
docker image inspect --format '{{.Id}}' ceo-ai-skillspector:2.12.0
```

Скопируй весь полученный `sha256:…` в переменную ниже. Адрес сокета замени на
разрешённый локальный адрес из шага 1. Одного тега адаптеру недостаточно.

```sh
CEO_SCAN_IMAGE='sha256:replace-with-the-full-image-ID'
CEO_SCAN_SOCKET='unix:///replace-with-the-approved/docker.sock'
docker run --rm --pull=never --network none --read-only --cap-drop ALL \
  --security-opt no-new-privileges --user 65534:65534 --pids-limit 64 \
  --memory 512m --cpus 1 "$CEO_SCAN_IMAGE"
```

Ожидаемый вывод: `SkillSpector 2.12.0`. Он проверяет запуск образа, но ещё не весь
аудит. Сборка, просмотр ID и сканирование должны использовать один локальный демон.

## 4. Проверь адаптер на искусственном примере

Выбери **новый** разрешённый приватный каталог вне проверяемого пакета. Его
родительские каталоги должны быть доверенными и недоступными другим пользователям
для записи. Замени путь в примере; не меняй права существующей папки ради обхода проверки.

```sh
mkdir -m 700 /approved/private-scan-workspace
python3 -I -B plugins/ceo-ai-security/skills/security-scan/scripts/ceo_security_nvidia.py \
  --package research/security-scanners/fixtures/skills/b01-summary \
  --workspace /approved/private-scan-workspace \
  --image "$CEO_SCAN_IMAGE" --version 2.12.0 --docker-host "$CEO_SCAN_SOCKET"
```

Перед продолжением этот пробный запуск должен вернуть JSON с `status: COMPLETE`
и код завершения `0`. Это означает, что адаптер отработал, а не что пакет безопасен.
Одного вывода версии недостаточно. Эта инструкция не подтверждает успешную
проверку всей цепочки на твоём компьютере.

## 5. Проверь один выбранный скилл

Повтори команду адаптера с `--package /approved/skill-directory` — каталогом,
содержащим `SKILL.md`. Оставь разрешённые рабочую папку, ID образа, версию и сокет.
При установке плагина используй `scripts/ceo_security_nvidia.py` относительно
загруженного `security-scan/SKILL.md`, не угадывай путь кэша. До сохранения JSON
согласуй приватный путь отчёта.

Для работы через навык начни новый чат: выбери `ceo-ai-security:security-scan`
в Codex или вызови `/ceo-ai-security:security-scan` в Claude Code.

Адаптер проверяет копию только для чтения, без сети и LLM. Код скилла он не
исполняет. Неподдерживаемые ресурсы приводят к отказу или неполному результату.
Код завершения `2` означает неполную проверку, а не отсутствие находок.

## Если проверка остановилась

| Проблема | Что делать |
| --- | --- |
| Docker недоступен или сокет неверный | Запусти разрешённый локальный демон и проверь Unix-сокет. Не открывай его по TCP. |
| Архитектура или синтаксис BuildKit не подходят | Остановись: нужны родной ARM64 и совместимый сборщик. Не обходи проверки. |
| Ошибка загрузки, хеша или версии | Проверь закреплённые входные данные. Не подменяй их тегом, незакреплённой зависимостью или новой версией сканера. |
| `unsafe_workspace` | Выбери новый разрешённый приватный каталог с доверенными родителями. Не ослабляй права. |
| Таймаут, пропуски или `INCOMPLETE` | Разбери причину и покрытие. Не переходи к платному API и не называй результат безопасным. |

После аварии, принудительной остановки или сбоя демона проверь оставшиеся ресурсы
только этого запуска. Не очищай Docker целиком. [Границы и очистка](SECURITY_SCANNING.md).

Проверка рецепта: модульные и статические проверки пройдены. В среде испытаний
не было Buildx, поэтому сборка образа и проверка всей цепочки там не завершены.
