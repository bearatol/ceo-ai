详细测试方案+

https://booking-staging.example.invalid 属于我们，范围仅限 /api/bookings/synthetic-17。仅用两个测试账号和虚构预约。审查预约处理代码；排除生产、支付及第三方系统。

缺少归属检查可能让一个账号读取别人的预约。建议用这两个账号向获准的 staging 预约端点逐次发送两次只读 GET，60 秒内结束，每次超时 5 秒，禁用重定向，不重试、不主动修改预约数据。读取可能暴露数据并留下日志。更安全的选项是只审查代码。遇到真实数据、不稳定或范围变化就停止；仅保留状态和虚构标记，之后丢弃本地测试客户端，不发送额外请求。是否批准这个方案？

你

在这个虚构故事中，我已阅读并批准上方完整的详细测试方案，包括确切目标、两次请求及 60 秒的限制、停止规则和本地清理。

Security

虚构结果：第二个账号也收到虚构预约标记。立即停止，报告归属检查缺失。其他端点未经测试，报告列出无法执行的检查。这不能证明整个应用安全。

↳先同意方案，以最小证据证明风险，说明覆盖缺口。

内置索引无需 Docker。

此索引工具需要 macOS、Linux 或原生 Windows（本地固定 NTFS 磁盘）上的 Python 3.10+。其静态分析有范围限制，不调用 LLM/API。AI 应用的对话 token 单独计算。Windows 拒绝网络驱动器、重解析点和包别名。

可选技能包扫描

无需 Docker 即可开始 Security 审查。此准备过程仅用于可选的 SkillSpector 技能包扫描。复制请求到 AI 应用，助手会检查兼容性并说明如何准备扫描器镜像。

当前构建方式：macOS 或 Linux 上的原生 ARM64 Docker 主机。Windows 内置检查不需要 Docker。

CEO AI / Q&A

开始前，了解这几件事。

CEO AI 正在积极开发中。我们持续测试这个协调任务的技能，并根据测试结果和反馈改进它。

查看安装帮助 ↗
会安装什么？+

源代码中包含 CEO、Writer、Security、Debugger 和 User Review。请查看所选版本包含哪些技能。项目安装和 APM 仅提供 CEO。不安装新模型、创建账户或自动注册智能体。

需要 Docker 吗？+

常规 Security 审查和内置索引检查不需要 Docker；只有可选 SkillSpector 技能包扫描才需要。支持的平台和设置方法见单独的 Docker 指南。

它只会赞同我吗？+

CEO 检查你提出的方案是否有助于实现目标。建议应基于证据、权威一手资料和适用的成熟实践，并明确说明缺口。决定权在你，赞同或反对都不应是自动反应。

哪些内容已经验证？+

已在 macOS 上检查插件安装、更新、卸载和技能发现。项目安装程序通过 Windows、Linux 和 macOS CI 验证。尚未验证模型调用。版本和限制见插件说明。

安装停止了怎么办？+

保留文件，让智能体说明冲突或缺少的权限。帮助文档介绍了找不到技能、更新中断以及从旧版迁移的处理方法。

AI 会出错，第二个 AI 的审查也可能出错。CEO 不会获得额外权限，也不能替代项目要求的安全审查。
