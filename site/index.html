SecurityTry the live site? First, agree the scope.+
Fictional example · Select: ceo-ai:security
You

Audit booking access. Can you try the live site?

Security

Which target do you own or have permission to test? Start with approved code; active tests need a specific plan and consent.

You

Our staging site, with fake bookings only. Production, payments and third-party systems are excluded; review the booking handler.

Security

Check whether one account can read another account’s booking, using the detailed plan below. Even reads can expose data and leave logs; code review alone is safer.

Detailed test plan+

We own https://booking-staging.example.invalid; scope: /api/bookings/synthetic-17. Two synthetic accounts and fake bookings only. Review the booking handler; no production, payments or third-party targets.

A missing ownership check could expose another account’s booking. Proposed proof: two sequential read-only GETs to the approved staging booking endpoint using those accounts, within 60 seconds, 5s per request, redirects disabled; no retries or intended booking-data writes. Reads can expose data and create logs. A safer option is code review alone. Stop on real data, instability or a scope change; keep only status and the fake marker, then discard local test clients without extra requests. Approve this exact plan?

You

In this fictional story, I have read and approve the full detailed test plan above, including its exact target, two-request/60-second limit, stop rules and local cleanup.

Security

Fictional outcome: the second account receives the fake booking marker. Stop and report the missing ownership check. Other endpoints were not tested; the report lists checks that could not run. This does not prove the entire app is safe.

↳Agree the test. Prove the risk minimally. Report the gaps.

Built-in indexing needs no Docker.

This indexing utility needs Python 3.10+ on macOS, Linux or native Windows (fixed local NTFS). Its bounded static analysis makes no LLM/API calls. Your AI app’s chat tokens are separate. Windows rejects network drives, reparse points and package aliases.

Optional skill-package scan

You can start a Security audit without Docker. This setup is only for the optional SkillSpector scan of skill packages. Copy the request into your AI app; the agent checks compatibility and explains how to prepare the scanner image.

Current recipe: native ARM64 Docker host on macOS or Linux. Native Windows builtin indexing does not require Docker.

CEO AI / Q&A

A few things to know.

CEO AI is under active development. We test and refine the orchestration skill based on test results and feedback.

Open the help guide ↗
What does it install?+

The source tree includes CEO, Writer, Security, Debugger and User Review. Check the selected release for its included skills. Project and APM installs provide only CEO. No new model, accounts or automatic agent registration.

Do I need Docker?+

Ordinary Security audits and the builtin inventory check need no Docker. Only the optional SkillSpector route for skill packages requires it. See the separate Docker walkthrough for the supported platform and setup.

Will it just agree with me?+

CEO checks whether your proposed solution serves your goal. Recommendations should follow evidence, authoritative primary sources and applicable established practices, with gaps stated clearly. You decide; neither agreement nor disagreement is automatic.

What has been tested?+

Native plugin installation, updates, removal and skill discovery were checked on macOS. The project installer is checked in Windows, Linux and macOS CI. Model invocation remains unverified. See the plugin guide for versions and limits.

What if installation stops?+

Keep your files. Ask the agent to explain the conflict or missing permission. The help guide covers missing skills, interrupted updates and older installations.

AI can be wrong. A second AI review can be wrong too. CEO gains no extra permissions and does not replace your project’s required security reviews.
